Qwen3.8-27B Unsloth GGUFs

Last scan Sat Nov 14, 15:53 UTC
2 sources · single origin (Unsloth)

Unsloth released new Dynamic v3.1 GGUF quantizations of Qwen3.8-27B, and a Reddit-sourced recap says the announcement graphic claims roughly 5–10% higher accuracy than Unsloth UD3, GSQ-RCO/ISTA and Exllama-3 on coding and agentic benchmarks.12 According to the post, the refreshed GGUF files span quantization levels from 2-bit to 6-bit, leaving out 3-bit. Agentic benchmarks were evaluated with a 256K context window, while the remaining tests used 128K. Hugging Face hosts the files, and the Unsloth documentation explains how the testing was done.34 The benchmarks named include Terminal Bench 2.1, DeepSWE v1.1 and LiveCodeBench v6, and a second recap adds that multiple repeated runs were used.56

A commenter questioned the chart's readability, saying many quant labels appear missing and that DeepSWE and Terminal Bench scores seem to drop from Q3 to Q4, which left it unclear which quant to pick for 24–32GB GPUs.78 Unsloth's danielhanchen replied that the main plots exclude token embedding sizes across all quant providers, while ExLlamaV3 stores token embeddings in BF16, so counting full download or RAM usage changes the size-versus-accuracy picture.910 Unsloth argues that counting real-world usage makes Exllama-v3 look worse, and danielhanchen speculated that the BF16 embedding layer may absorb some quantization damage, saying future tests of non-BF16 embeddings such as 8-bit are possible.111213

Separately, a user asked whether a tokenizer-pruning workflow using ASCII-Condensed-prune-tools, which lets a Q4 Qwen 3.8 27B fit on a 16GB GPU, would remain compatible with the new GGUFs.1415

In a related thread about the MLX quantization method KQuant, commenters asked how it compares with Unsloth Dynamic v3.1 and noted that EXL3 and EXL3-SC were omitted from its comparison.1617
