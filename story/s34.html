Claude app speedups

2 sources · tracked since Sep 27 · single origin (Anthropic)

Anthropic says it made the core user experience of claude.ai and the Claude desktop app about 3x faster in a two-week sprint, after users had said it was slow.12 Zvi Mowshowitz's roundup relays Anthropic's claim of a 3x speedup over two weeks and notes that Claude Code saw a smaller speedup and that the figures exclude time spent by Claude itself.34

Anthropic reports that at the 75th percentile, time to a typeable page on a fresh claude.ai load fell from 3.1 seconds to 0.55, starting a new Claude Code session fell from 0.8 to 0.3 seconds, and loading a Claude Cowork cloud session fell from 2.6 to 0.73 seconds.56 Anthropic estimates this saves tens of thousands of user-hours of waiting every day, and says the work focused on four journeys making up 95% of user activity.78

Anthropic says it used Claude Tag (beta), running an internal research model roughly comparable to Opus 5.5, which found bottlenecks, built benchmarks, shipped improvements and watched every deploy, while humans set goals and approved every change.91011 The company says it merged more than three thousand changes without a single customer-facing incident or rollback, using incremental rollouts to employees, then one percent of users, then everyone for high-risk changes.1213

Examples Anthropic cites include Claude finding a :root:has() selector adding 24 milliseconds to every DOM change, and a leftover location.reload() causing half a million hidden reloads a day.1415 In one thread on long replies, Anthropic says main-thread blocking dropped from about 750 to about 200 milliseconds, with 120 fps held on a 120 Hz MacBook.1617

Anthropic acknowledges the work is unfinished: the 95th percentile, other journeys, and very long conversations still have room to improve, and an engineer named Issac said, "You could not have convinced me this was possible even six months ago."1819

What did Anthropic do to make sure the changes didn't break anything, and how did the Chrome prerender layout-shift bug get caught and fixed?

Anthropic says the team steered by setting goals, making tradeoffs and approving every change, while Claude found bottlenecks, built benchmarks, shipped improvements and watched every deploy.12 The team also used incremental rollouts, sending high-risk changes to employees first, then to one percent of users, then to everyone.3 Claude also built a benchmark test for layout shifts. It failed 20 of 20 runs on the main branch and passed 20 of 20 runs on the fix.4 The Chrome bug surfaced during the internal rollout. Four hours after the static composer was released internally, a teammate shared a screen recording of a layout shift that none of the team's metrics could see.5 Claude traced the shift to Chrome prerendering the page from the address bar at the height of the current tab. On organization-managed browsers that new-tab page is slightly shorter because of a footer, so the page was resized about a tenth of a second after first paint.678 Anthropic's existing layout tests missed the bug because headless Chrome has no browser UI to retract. The fix was for Claude to pin the layout across the resize, and the team added a test that simulates the prerender flow.910

Why did an em dash or curly quote in a reply freeze the page while code was being highlighted, and how was it fixed?

Anthropic says Claude noticed during a sweep for CPU hitches that highlighting a finished code block could freeze the page for about a second, and traced the cause to em dashes.12 According to Anthropic, if a reply's markdown contained any non-Latin-1 character, such as an em dash or a curly quote, V8 stored the entire string as UTF-16, which pushed every syntax-highlighting regex onto its slower two-byte path.3 Anthropic says the fix was a twenty-line change that copies each code block into a one-byte string before it is highlighted.4

How did Anthropic choose the four journeys to focus on, and how many separate measurements did it track?

Anthropic says it had Claude analyze usage data through the Datadog MCP server, and Claude identified the four highest-impact user journeys.1 The journeys were launching the app, starting a conversation, loading an existing conversation and sending a message.2 Anthropic says those four journeys account for 95% of user activity.3 Across web, desktop and its products, the journeys came to thirteen distinct measurements, according to Anthropic.4
