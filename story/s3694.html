Claude Code settings secrets leak

Last scan Sat Nov 14, 15:53 UTC
2 sources · 626 points on Hacker News · single origin (Apiiro)

Security firm Apiiro reports that Claude Code is leaking sensitive information on public GitHub repositories, because its local settings files are sometimes committed and uploaded with secrets inside them.12 The cause is that choosing "Yes, and don't ask again" for a shell command stores a rule in .claude/settings.local.json, and the command is often written out as is, including any embedded sensitive data.34 Anthropic's documentation says this file is added to the developer's global .gitignore, but that setting does not carry over at the repo level, so the file can be uploaded if a repo is cloned elsewhere or a folder later becomes a repo.56

Apiiro found over 100,000 cases of the settings file in public repositories, of which only about 1,100 from 63 organizations contained secrets, and the secrets can persist in forks even after removal.789 Apiiro also found that 215 of the roughly 1,100 secrets were not flagged by the secret scanners gitleaks and TruffleHog.10

According to Ars Technica, the problem was flagged in a Claude Code bug report as early as August 2025, and several related reports were closed without action after 60 days of inactivity.1112

Claude Code's Boris Cherny said on Hacker News that the team is looking into prevention, while arguing that such files should almost never be checked in and that cases seemed to arise only when the files were manually created and checked in.1314 Cherny recommended auto mode and secret scanners, and after a user noted that sensitive commands can still be saved in auto mode, he called it a "good catch" and said the team is considering improvements, including possibly building in secret scanning.151617
