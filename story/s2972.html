OpenAI Pando Git backend

Last scan Sun Nov 8, 08:53 UTC
3 sources · 271 points on Hacker News · tracked since Nov 6 · single origin (OpenAI)

OpenAI says it built Pando, a new backend for Git repositories, to scale its monorepo to the level of concurrent work that its Codex coding agent makes possible, and that Pando now powers all development in that monorepo.12 According to OpenAI, Pando keeps compatibility with the Git protocol and client, and it was rolled out without interrupting engineering work or changing how the team uses Git.34

OpenAI says Pando was built with Codex from kick-off to production in 10 weeks, with its core designed by a single engineer, implemented by teams of agents and deployed by a handful of engineers, and that it began serving production traffic in April.567

OpenAI says the design handles pushes by validating the incoming packfile while streaming it to blob storage, without unpacking it into a local repository, so servers mainly negotiate and select packs and can run on commodity hardware.89 In a simulation OpenAI published, modeled three-phase commit systems show much higher write latency under load and write-ahead log systems much higher read latency, while Pando supports many thousands of concurrent pushers without performance impact; this is OpenAI's own comparison.1011

OpenAI reports that Pando cut median push latency by nearly 5x (about 80%) and now delivers nearly a petabyte of Git data per day.1213 OpenAI also says Pando has served more than 57 terabytes of Git packs in a single hour, with more than 99% of those bytes from local disk cache, and can deliver a petabyte per day with just a handful of CPU cores.1415

Jones argues that when one part of work accelerates, the rest of the organization must handle the change, so individual engineers become more productive while the team delivers far less of that gain.16
